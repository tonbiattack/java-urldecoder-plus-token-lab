# 題材重複調査レポート: `URLDecoder`がプラス記号を空白へ変換する

## 調査対象

| 項目 | 内容 |
| --- | --- |
| 対象言語 | Java 21 |
| 難易度プロファイル | 実践・上級 |
| 候補題材 | `URLDecoder.decode("AB+CD", UTF_8)`により、プラス記号を含む不透明トークンが`AB CD`へ変換され、照合に失敗する問題 |
| 観測可能な契約 | `BASE42`を受理済みの状態で`AB+CD`を受理し、最後のトークンと受理件数を更新すべきだが、バグ状態では拒否されて旧状態が残る。 |
| 直接原因 | フォーム用の`URLDecoder`を不透明トークンへ適用し、`+`を空白へ変換していること。 |
| カタログ更新日時 | Repository Catalog（`/home/ubuntu/repository-catalog`）は存在しなかったため更新・検証は実施不能。代替として、ユーザー指定の`tonbiattack/qiita`を取得し、Java・URLDecoder・URLEncoder・フォームエンコード・プラス記号・Base64を本文とパスから検索した。 |
| 検索語 | `Java`, `URLDecoder`, `URLEncoder`, `フォームエンコード`, `application/x-www-form-urlencoded`, `プラス記号`, `Base64` |

Repository Catalogが利用できなかったため、このレポートの新規性判断は指定コンテンツリポジトリを対象とします。カタログに未登録のローカル専用教材までは保証できない限界を明示します。

## 結論

**作成する。**

エンコード済みデータやBase64ストリームに近接する記事は確認できましたが、`URLDecoder`の**プラス記号を空白へ変換するフォーム規則**を直接原因として、不透明トークンの受理結果・最後のトークン・受理件数を扱う記事・教材は見つかりませんでした。

既存のBase64InputStream記事とは、変換ストリームの戻り値契約か、フォームデコード規則とトークン値保持かが異なります。実境界、観測契約、最小修正も独立しているため、教育上意味のある追加題材と判断しました。
